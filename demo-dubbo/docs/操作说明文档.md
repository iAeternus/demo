# Dubbo RPC Demo 实验指南

## 1. 快速开始

### 环境要求
- JDK 17+
- Maven 3.9+
- Docker + Docker Compose (WSL2)

### 启动步骤

```bash
# 1. 进入Docker目录
cd docker

# 2. 启动所有服务（首次构建镜像）
docker-compose up -d --build

# 3. 查看服务状态
docker-compose ps
```

### 服务端口
| 服务 | 端口 | 说明 |
|------|------|------|
| Zookeeper | 2181 | 注册中心 |
| Provider | 8081 | 服务提供者 |
| Consumer | 8082 | 服务消费者 |

## 2. 实验观测

### 2.1 基本功能测试

```bash
# 创建用户
curl -X POST "http://localhost:8082/users?name=ricky"

# 获取用户列表
curl http://localhost:8082/users

# 获取单个用户
curl http://localhost:8082/users/1
```

### 2.2 观测注册中心

```bash
# 进入Zookeeper容器
docker exec -it dubbo-zookeeper zkCli.sh -server localhost:2181

# 查看已注册服务
ls /dubbo/com.ricky.service.UserService/providers
ls /dubbo/com.ricky.service.UserService/consumers
```

### 2.3 观测日志

```bash
# 查看所有服务日志
docker-compose logs -f

# 查看特定服务日志
docker-compose logs -f provider
docker-compose logs -f consumer

# 查看Zookeeper日志
docker-compose logs -f zookeeper
```

### 2.4 观测容器状态

```bash
# 查看容器健康状态
docker-compose ps

# 查看容器资源使用
docker stats

# 查看容器详细信息
docker inspect dubbo-provider
docker inspect dubbo-consumer
```

### 2.5 观测网络

```bash
# 查看自定义网络
docker network ls | grep dubbo

# 查看网络详情
docker network inspect docker_dubbo-net
```

### 2.6 观测JVM和进程

```bash
# 进入Provider容器
docker exec -it dubbo-provider sh

# 查看Java进程
ps aux | grep java

# 查看内存使用
free -h

# 查看打开的端口
netstat -tlnp
```

### 2.7 健康检查端点

```bash
# Provider健康检查
curl http://localhost:8081/actuator/health

# Consumer健康检查
curl http://localhost:8082/actuator/health
```

## 3. 停止服务

```bash
# 停止并删除容器
docker-compose down

# 停止并删除容器、网络、卷
docker-compose down -v

# 删除构建的镜像
docker-compose down --rmi local
```

## 4. 常见问题

### 4.1 服务启动失败
```bash
# 查看详细日志
docker-compose logs service_name
```

### 4.2 Zookeeper连接失败
```bash
# 检查Zookeeper是否正常运行
docker-compose logs zookeeper

# 测试Zookeeper端口
telnet localhost 2181
```

### 4.3 Dubbo服务未注册
```bash
# 检查Provider日志
docker-compose logs provider

# 确认注册地址正确
# application.yml中应为: zookeeper://zookeeper:2181
```

## 5. 生产部署要点

1. **健康检查** - 确保依赖服务就绪后再启动
2. **JVM资源限制** - 防止内存溢出
3. **非root用户运行** - 增强安全性
4. **日志管理** - 生产环境需接入日志收集系统
5. **监控告警** - 建议接入Prometheus + Grafana
