# Dubbo RPC Demo 实验指南

## 1. 快速开始
### 环境要求
- JDK 17+
- Maven 3.9+
- Docker + Docker Compose（建议 Docker Desktop + WSL2）

### 启动步骤

```bash
# 1. 进入 docker 目录
cd demo-dubbo/docker

# 2. 构建并启动全部服务
# 说明：docker-compose.yml 的 build.context 指向仓库根目录
# 首次启动建议加 --build
sudo docker-compose up -d --build

# 3. 查看服务状态
sudo docker-compose ps
```

### 服务端口
| 服务 | 端口 | 说明 |
|------|------|------|
| Zookeeper | 2181 | 注册中心 |
| Provider | 8081 | 服务提供者 |
| Consumer | 8082 | 服务消费者 |

## 4. 常见问题

### 4.1 构建报错：路径重复或找不到 Dockerfile
**现象**：`failed to build: resolve : lstat .../demo-dubbo/demo-dubbo: no such file or directory`

**原因**：`docker-compose.yml` 中 `build.context` 和 `dockerfile` 的组合路径不正确。

**解决**：
- 确保 `demo-dubbo/docker/docker-compose.yml` 中：
  - `build.context` 为 `../..`（仓库根目录）
  - `dockerfile` 为 `demo-dubbo/docker/Dockerfile`

### 4.2 构建报错：根 POM 子模块不存在
**现象**：`Child module /build/demo-xxx of /build/pom.xml does not exist`

**原因**：在镜像构建阶段直接使用根 `pom.xml` 运行 Maven，导致 Maven 尝试解析仓库内其它模块，但这些模块未被复制进镜像构建上下文。

**解决**：
- Dockerfile 中应先安装根 POM，再使用 `demo-dubbo/pom.xml` 构建子模块：
  - `mvn -f pom.xml install -N -B`
  - `mvn -f demo-dubbo/pom.xml clean package -DskipTests -B`
- 并确保 `demo-dubbo` 目录结构在构建镜像时完整复制。

### 4.3 构建卡在依赖下载
**现象**：构建日志长时间停在某个依赖下载。

**原因**：网络不稳定或 Maven 连接复用导致卡住。

**解决**：
- 已在 Dockerfile 中加入 Maven 下载重试与连接策略（无需额外操作）。
- Dockerfile 内已将 Maven 中央仓库镜像指向阿里云 `ali-public`。
- 如仍卡住，建议清理后重试：`sudo docker-compose build --no-cache`

### 4.4 容器反复重启：no main manifest attribute
**现象**：容器日志出现 `no main manifest attribute, in app.jar`。

**原因**：Spring Boot 可执行 Jar 未打包（缺少 `spring-boot-maven-plugin`）。

**解决**：
- 确保 `dubbo-provider` 和 `dubbo-consumer` 模块中配置了 `spring-boot-maven-plugin`。

### 4.5 服务启动失败

```bash
# 查看详细日志
sudo docker-compose logs service_name
```

### 4.6 Zookeeper 连接失败

```bash
# 检查 Zookeeper 是否正常运行
sudo docker-compose logs zookeeper

# 测试 Zookeeper 端口
telnet localhost 2181
```

### 4.7 Dubbo 服务未注册

```bash
# 检查 Provider 日志
sudo docker-compose logs provider

# 确认注册地址正确
# application.yml 中应为 zookeeper://zookeeper:2181
```

## 5. 生产部署要点

1. **健康检查** - 确保依赖服务就绪后再启动
2. **JVM 资源限制** - 防止内存溢出
3. **非 root 用户运行** - 增强安全性
4. **日志管理** - 生产环境需接入日志采集系统
5. **监控告警** - 建议接入 Prometheus + Grafana
